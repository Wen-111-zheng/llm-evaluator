# LLM 输出质量自动评测工具

一个给大模型"出考卷、自动阅卷"的小工具：把一批问题丢进去，它调大模型拿到回答，再按**四个维度自动打分**、揪出 Bad Case，最后生成一份带图表的 HTML 报告。

> 这是我学 LLM 应用工程时写的——当时最大的困惑是"我调的 prompt / 模型到底靠不靠谱？凭感觉说不清"。这个工具就是逼自己把"质量"变成可量化、可复现的数字。

---

## 一、我为什么做这个

调 prompt 的时候，我发现自己一直在用"感觉还行"来评价效果，这没法迭代——你改了一版，到底是变好还是变坏，全靠记忆和印象，很容易自欺。

所以我写了这个工具：准备一份题目集（`data/questions.jsonl`，每题标好"期望关键词""合理长度区间"），让模型作答，再用规则自动判分。这样**每一次改动都能跑一遍、出一份得分对比**，迭代就有了依据。

---

## 二、最终长什么样

```
准备题目集 questions.jsonl
        │
        ▼
┌──────────────────┐   调 DeepSeek    ┌──────────────────┐
│   evaluator.py   │ ───────────────► │  模型回答        │
│  （评测引擎）     │                 └──────────────────┘
└──────────────────┘
        │ 四维度打分
        ▼
   关键词覆盖 / 长度合理性 / 格式规范 / 安全性  (各 0-25，总分 0-100)
        │
        ▼
   总分 < 60 或 安全性 < 15  →  标记为 Bad Case
        │
        ▼
   输出 output/eval_results.json
        │
        ▼
┌──────────────────┐   读 JSON        ┌──────────────────┐
│   reporter.py     │ ───────────────► │ HTML 报告 + 图表  │
└──────────────────┘                  └──────────────────┘
```

## 三、四个评分维度（我的设计取舍）

| 维度 | 满分 | 怎么算 | 为什么放这一维 |
|---|---|---|---|
| 关键词覆盖 | 25 | 期望关键词命中比例 | 检验"该说的点有没有说到" |
| 长度合理性 | 25 | 回答长度落在 [min,max] 区间给满分 | 太短答不全、太长易灌水 |
| 格式规范 | 25 | 有分段、有标点结尾、无异常 | 真实应用里格式就是体验 |
| 安全性 | 25 | 命中脏话/不当词扣分到 0 | 底线，不达标直接 Bad Case |

**总分 < 60，或安全性 < 15** → 判定为 Bad Case，报告里单独拎出来分析。

## 四、我亲手做的实验与结论

- **实验：temperature 对"发散度"的影响**
  我单独对比过 `temperature=0` vs `0.7` 的作答——低温更稳、更贴关键词；高温更有创意但长度和安全分波动更大。结论：**评测和线上用同一套温度才有可比性**，否则数字没意义。

- **实验：max_tokens 卡太狠会"答一半"**
  把上限压到 200 时，长问题经常被截断，长度和关键词分双双跳水。结论：**max_tokens 至少要覆盖"最长合理回答"，否则是在评测截断而不是评测质量。**

- **我对自动评测的判断（不是抄共识）**
  - 关键词覆盖只能测"有没有提到"，**测不出"说得对不对"**——所以它必须配合人工抽检，不能当唯一标准。
  - 自动评测真正的价值是**回归对比**：同一题集，改一版 prompt 跑一遍，看均分和 Bad Case 数是升是降，迭代才有方向。
  - 安全性这一维不能省，哪怕它很简单——它是唯一一条"一票否决"的底线。

## 五、踩过的坑

- **中文图表乱码**：matplotlib 默认不含中文字体，需要显式指定 `Microsoft YaHei` 并关掉 unicode minus，否则图里全是方框。
- **API 限流**：逐题调用之间 `sleep(1)`，避免触发 DeepSeek 频率限制。
- **密钥管理**：`config.py` 从环境变量 `DEEPSEEK_API_KEY` 读 Key，仓库里绝不出现明文。

---

## 六、怎么跑

```bash
# 1. 安装依赖
pip install -r requirements.txt

# 2. 配置 Key（仅运行时需要，不写进代码）
export DEEPSEEK_API_KEY=你的key        # Git Bash / Linux / macOS
# set DEEPSEEK_API_KEY=你的key         # Windows cmd

# 3. 跑评测（生成 output/eval_results.json）
python evaluator.py

# 4. 生成报告（output/eval_report.html + score_chart.png）
python reporter.py
```

打开 `output/eval_report.html` 即可看到得分卡片、逐题明细表和 Bad Case 分析。

## 七、文件结构

```
llm_evaluator/
├── evaluator.py            # 评测引擎：调用模型 + 四维度打分 + Bad Case 判定
├── reporter.py             # 报告生成：HTML 可视化 + matplotlib 图表
├── config.py               # 模型 / 评测参数 / 输出路径
├── requirements.txt
├── data/
│   └── questions.jsonl     # 题目集（每题含期望关键词、长度区间）
└── output/                 # 运行生成（自动生成，不入库）
    ├── eval_results.json
    ├── eval_report.html
    └── score_chart.png
```
